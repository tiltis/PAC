# 두 도구가 이어서 작업하는 방법

공유 기준은 `https://github.com/tiltis/PAC`의 `tiltis/`다. 이 노트북에서는 `PAC_team_source/tiltis/`를 사용한다. 기존 바깥 `pac_minimal/`은 이전 작업본이며, 이후 손목 제어 변경은 `codex/pac_minimal/`에서 한다.

## 작업 시작

1. `git status`로 남은 변경을 확인하고 `git fetch origin`으로 원격을 확인한다. 미커밋 변경을 보존하며 동기화한다.
2. 양쪽 `HANDOFF.md`와 관련 커밋/차이를 읽는다. 다른 도구가 이미 구현한 부분을 먼저 찾는다.
3. 재사용할 코드의 입력·출력·단위·좌표·SDK 버전·정지 동작을 확인한다. 맞으면 이어서 연결하고, 문제가 있으면 실패 사례를 만들고 수정한다.
4. 같은 파일을 동시에 편집하지 않는다. 병행할 때 작업 파일을 나누고 완료된 변경을 Git으로 통합한다.

## 작업 완료

자기 `HANDOFF.md`에 변경 이유와 파일, 실제 실행한 테스트와 결과, 상대 구현 검토 결과, 남은 장비 확인 사항을 기록한다. 상대 코드 변경은 해당 폴더 인계에도 근거를 남긴다. 코드와 기록을 함께 커밋하고 사용자 승인 범위에서 push한다.

읽기 전용 Claude 리뷰도 `claude-code/`에 결과를 보관한다. 제기된 문제는 Codex가 코드·재현 테스트로 확인해서 반영하거나 미반영 이유를 기록한다. 각 도구를 실행할 때 이 순서를 따른다. 이 문서만으로 상시 자동 실행이 시작되는 것은 아니다.

## 현재 연결 경계

- 검사: 센서(8001) ↔ 스테이션(8000), 기존 `CONTRACT.md`를 기준으로 한다.
- 손목: 비전(5001) `/api/state` ↔ `robot_bridge.py`, `position_m`은 m, `robot_base`, 고정 Z다.
- 같은 카메라나 로봇 포트를 두 프로그램에서 동시에 점유하지 않는다. 기존 배포 서버는 자동 종료·설정 변경하지 않는다.
- 실제 로봇 CLI는 아직 없다. SO-101 어댑터는 후보이며 모델 확정·보정·실기 검증을 대신하지 않는다.
- 로그는 순차 timestamp 기록이다. 영상과 실제 관절/EE 후속 관측의 동기화 확인 전 학습용 실측 데이터로 주장하지 않는다.
