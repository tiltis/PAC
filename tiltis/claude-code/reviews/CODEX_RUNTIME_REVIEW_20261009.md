사용자 요청: Claude Code가 만든 코드에도 접근하여 기존 구현을 참고할 것.

공유 소스 `tiltis/claude-code/PAC2026_system/`와 실제 배포 폴더
`C:/PAC2026_system/`를 직접 읽고 비교했다. 검토 시 Git HEAD와 origin/main은
`3c4cef4`로 같았지만, 실행 폴더에는 아직 공유 소스에 없는 변경이 있다.
실행 파일, 서버, 카메라, COM8, 실측 자세/보정은 수정하거나 실행하지 않았다.

## 재사용할 기존 구현

- `station/robot.py`: LeRobot `SO101Follower`/`SO101FollowerConfig`,
  `use_degrees=True`, 실제 관절 관측, 별도 그리퍼 명령, 현재 관절 목표로 hold.
  별도 SDK 어댑터를 중복 구현할 필요가 없다.
- `station/kinematics.py`: 기존 URDF FK/IK와 m·rad ↔ LeRobot deg 변환.
  실행본과 공유본 내용이 같다.
- `sensor/depth.py`: 기존 Gemini2 깊이 수집. 실행본과 공유본 내용이 같다.

## 실행본의 추가 변경과 통합 조건

- `station/grasp.py` (검토 당시 수정 시각 19:06:19): 접근점을 뒤와 위로
  조정하고, 손가락/턱 중심 오프셋을 보정하며, `_ik_near()`로 집기 자세에
  가까운 접근/들기 IK 해를 찾는다. 유용한 통합 후보다. 도구 오프셋은 현장
  TCP 확인이 필요하며, 기준 관절에 가까운 해가 경로 충돌을 보장하지 않는다.
- 같은 실행본은 여전히 `radial`로 접근과 yaw를 정하고, 턱 오프셋 계산 중에도
  radial/yaw를 반복 갱신한다. 그대로 복사하면 공유 소스의 `side_box_alignment()`
  (측정한 상자 두 3D 축에 접근/집게 정렬)이 사라진다. 상자 방향과 도달 불가
  거부를 유지하면서 접근 높이·TCP·IK 분기 선택을 통합해야 한다.
- `side_use_absolute_z`는 카메라 높이 대신 로봇 기준 절대 높이를 쓰는 옵션이다.
  설치 좌표 보정의 대체 수단으로 취급하지 않는다. min tip Z, 관절 이동 허용치,
  접근/들기 높이도 실측 경로 검증 없이 승인값으로 복사하지 않는다.
- `station/sequencer.py` (19:20:24): 검사/분류 이동 시간 증가, 안정화 대기 연장,
  빈 집기 후 home으로 시야 확보, `dry_stage=grasp`의 관절/FK 오차 로그가 추가됐다.
  관측 관절, 명령 관절, FK TCP와 계획 TCP 비교는 상태–행동 기록의 재사용 후보다.
  FK TCP는 관절과 모델에서 계산한 값이며 독립적으로 측정한 EE 위치가 아니다.
  또한 이 코드의 `dry_run`은 실제 접근/집기 위치로 이동하므로 읽기 전용 시험이 아니다.
- 실행 sequencer에는 공유본의 `preflight_ready()`, 접근/재시도 후
  `_verify_before_grasp()`, 작업에서 계산한 `_vision_lift` 재사용 연결이 없다.
  통합 시 해당 연결을 보존해야 한다.
- `station/robot.py` (19:02:46): 안정화 관절 허용 오차가 2°에서 5°로 변경됐다.
  도달/안정화 판정에 영향을 주므로 그대로 완화하지 않는다. 실제 TCP 오차,
  하중, 제어 게인과 함께 확인해야 한다.

## 좌표 등록 경계

`sensor/registration.py`는 열화상 LWIR와 RGB 사이의 면별 평면 homography다.
SAM에 필요한 외부 RGB(Arducam)와 Gemini2 깊이의 3D R/t 정합이 아니다.
등록 파일 이름만 보고 두 보정을 혼용하지 않는다.
`registration.py`와 `handeye.py`는 원시 파일 해시는 달랐으나 줄바꿈/BOM을
정규화한 코드 내용은 공유본과 같았다.

## 이번 검증 범위

읽기 전용으로 확인했다. 이번에는 기능 코드를 바꾸지 않았으므로 자동 테스트나
실기 시험을 새로 실행하지 않았다. 앞선 SAM/깊이/IK 테스트 결과는 이 배포본에
새로 추가된 TCP/IK/오차 기록 변경을 검증한 결과가 아니다.
